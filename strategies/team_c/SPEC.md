## C2 — 변동성 압축 → 거래량 동반 돌파 (1h) (`strategies.team_c.c2_squeeze:C2Squeeze`)

| 단계 | 내용 |
|---|---|
| 출처 | C03 1위 '변동성 방향성' 라벨(공식 수상 페이지, 규칙 미공개) / C02 비용 비중(연구자 산출) — 빈번 매매 억제 근거 |
| 원칙 | P3 방향성 + P7 국면 적응: 변동성 압축 국면 뒤의 방향성 확장을 노린다. P6(비용): 압축+거래량 조건으로 거래 빈도를 제한한다. |
| 정량 가설 (자체 가정) | 1h ATR14/ATR100이 최근 30일 기준 하위 20%인 압축 상태 뒤, 범위 ≥ 1.5×ATR14 이고 거래량 ≥ 2×20봉 중앙값인 돌파봉 방향을 따르면 비용 차감 후 평균 R > 0. |
| 코드 규칙 | ① 압축: ATR14/ATR100(TR의 단순평균)의 720봉 롤링 백분위(현재 봉 포함, 과거만) ≤ comp_pct(0.20), **직전 봉(t−1) 기준**(돌파봉이 자기 ATR을 부풀리는 것을 피함, 자체 가정) ② 트리거(봉 t): high−low ≥ 1.5×ATR14[t−1], volume ≥ 2×median(volume[t−20..t−1]); 종가가 봉 상단 1/3 → 롱, 하단 1/3 → 숏; 미완성 봉(complete=False)은 진입 없음 ③ 손절: 돌파봉 반대 끝 ④ 청산: exit_mode=both → 3R 익절 + 2.5×ATR14 추적(진입 후 최고/최저 종가 기준, 조이기만), tp → 3R만, trail → 추적만; 최대 48봉 보유 후 target 0 ⑤ 펀딩 필터: 봉 종료 시각까지 실현된 마지막 펀딩이 진입 방향에 불리하고 \|rate\| > 0.05%/8h면 진입 안 함 ⑥ 크기: 공통 엔진(0.25%×자본/손절폭, 3배 상한) ⑦ 포지션 추적: 전략 내부 그림자 포지션(봉 고가/저가로 손절·익절 접촉 판정)으로 매 봉 target/stop을 낸다 |
| 검증 지표 | 비용 차감 순수익률, MDD, 수익/MDD, Sharpe, 거래 수, 승률, PF, 손익비(≈R 분포), 거래량 필터 제거·펀딩 필터 제거 비교, comp_pct 15/20/30 민감도, BTC·ETH 개별, 비용 스트레스(spread×3, impact×3, latency 1000ms) |

## C1 — 변동성 국면 게이트 + 변동성 목표 크기 (1h) (`strategies.team_c.c1_regime:C1Regime`)

| 단계 | 내용 |
|---|---|
| 출처 | C04·C05 (주최측 발표: 위험 통제형 AI팀이 청산 0, 집단 ROI 우위) / C01 (시장 조건에 맞춰 도구를 고른다는 발언) |
| 원칙 | P2 생존(청산 회피) + P7 국면 적응: 극단 변동성 국면에서는 새 위험을 지지 않고, 변동성이 높을수록 크기를 줄인다. |
| 정량 가설 (자체 가정) | 24h 실현변동성의 90일 백분위 > 95에서 신규 진입을 막고 변동성 비례로 크기를 줄이면, 게이트 없는 같은 추세 진입보다 MDD가 상대 20% 이상 낮고 Sharpe는 같거나 높다. |
| 추세 진입 (팀 C 자체 선언, 자체 가정) | 1h 종가 > 직전 20봉 최고가 → 롱, < 직전 20봉 최저가 → 숏; 초기 손절 종가 ∓ 2.0×ATR14; 진입 후 최고(최저) 종가 ∓ 3.0×ATR14 추적(조이기만); 반대 돌파 시 청산(게이트가 열려 있으면 반대 진입). 추세 필터·최대 보유 없음. |
| 코드 규칙 | ① RV = 1h 로그수익률 24봉 표준편차; p = RV의 2160봉(90일) 롤링 백분위(과거만, min_periods 720 — 실행기의 60일 warm-up 때문에 split 초반 30일은 90일보다 짧은 창, 자체 가정) ② p > 0.95 → 신규 진입 금지(보유 포지션은 손절·추적 유지) ③ size_mult: `rel`(기본) = min(1, median_90d(RV)/RV); `abs` = min(1, 목표연변동성/RV_연율 ÷ (0.25%/손절비율)) — 근거 문서 ③(명목가 = 목표변동성/RV × 자본)을 엔진의 위험 단위로 환산한 것. 엔진은 크기를 **줄이기만** 하므로 3배 상한 대비 확대는 불가 ④ 일일 손실 2% 정지·10% 낙폭 정지는 공통 엔진 |
| 검증 지표 | 비게이트 대비 MDD 변화율(목표 ≤ −20%), Sharpe, 수익/MDD, 순수익률(게이트 기회비용), 거래 수, 일일 손실 한도 도달 횟수(events), 비용 스트레스 |

## 실험 계획 (결과 보기 전 기재, 2026-10-09 18:07 KST)

- 튜닝은 train(2021-10-09~2024-09-30)만. validation(2024-10-01~2025-09-30)은 아래 사전 선언 변형 안에서만 선택. test 사용 안 함. 예산 ≤ 30회, 실패 포함 전부 등록.
- train (BTC+ETH): C2 기본(q20, both) / q15 / q30 / exit tp / exit trail / 거래량 필터 off / 펀딩 필터 off; C1 비게이트(size none) / 게이트+rel / 게이트만(size none) / 게이트+abs(목표 연변동성 0.5).
- validation 선택 후보(사전 선언, ≤5): C2 기본, C2 q15, C2 q30, C2 train 최고 exit 변형(기본이 최고면 생략); C1 게이트+rel (비게이트는 비교 기준선으로 함께 실행). 거래량 off·펀딩 off는 진단용이며 선택 대상이 아님.
- 선택 후보에 추가: BTC 단독·ETH 단독, 비용 스트레스(spread=3, impact=3, latency=1000).
- 선택 기준(동결 프로토콜): validation 비용 차감 net_return / max_dd, 거래 ≥ 30. 현금(0%)을 이기지 못하면 정직하게 표기.

### train 결과 후 validation 실행 전 확정 (2026-10-09 18:12 KST, validation 0회 상태)

- train 11회 모두 10% 낙폭 정지에 도달(정지 시점 이후 거래 없음). 따라서 train 비교는 정지 시점까지의 거래 단위 R과 정지 시점으로 본다.
- C2 exit 변형 중 train 최고는 `exit_mode=trail`(유일한 양(+) 순수익, 평균 순 R +0.05). 기본 both(3R 익절)는 −0.07R, tp만은 −0.54R.
- T7(펀딩 필터 off)은 T1과 완전히 같았다: train 기간에 |펀딩| > 0.05%/8h 인 불리한 진입이 없었다. T11(abs, 목표 0.5)은 T10과 같았다: 엔진이 크기를 줄이기만 하므로 손절 2×ATR 기준 위험 크기가 목표 변동성 명목가보다 이미 작아 size_mult가 항상 1이었다(설계상 한계, 기록).
- **validation 선택 후보(확정)**: C2-V1 기본(q20, both) / C2-V2 q15 / C2-V3 q30 / C2-V4 trail(q20); C1-V5 게이트+rel. 비교 기준선: C1 비게이트. 진단: C2 trail의 거래량 off·펀딩 off, BTC·ETH 단독, 비용 스트레스. C2 trail 인접 안정성 진단: trail q15·q30는 예산 여유 시.

해석:
- C2 가설(비용 차감 평균 R > 0)은 validation에서 **기각**(모든 사전 선언 변형 음(−), 평균 순 R −0.15~−0.26). train 총 R은 양(+)이었으나 비용(≈0.1R/거래)이 대부분을 잠식했다. 3R 익절보다 추적 청산이 낫다는 점은 우측 꼬리 의존(P4)과 일치한다.
- C1 가설(MDD 상대 −20% 이상)은 **미달**. 게이트는 진입의 약 10%만 막고, `abs` 목표 변동성 크기는 엔진이 크기를 줄이기만 하므로 2×ATR 손절 기준에서 한 번도 작동하지 않았다.
- 거의 모든 실행이 공통 10% 낙폭 정지에 걸려 이후 구간이 비어 있다. 그래서 순수익·MDD 비교는 정지 시점에 좌우된다. 결론: **현금을 이긴 후보 없음(검증 불충분/폐기 수준)**.
- 그림자 포지션 한계: 엔진이 진입을 거부(일일 손실 차단·미완성 봉)하면 다음 봉에 같은 target이 다시 나가 늦은 진입이 생길 수 있다.
