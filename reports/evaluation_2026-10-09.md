## 1. 방법

- **동일 조건**: `scripts.run_experiment.run`(register=True, team=`eval`)으로 5개 후보 모두를 현재 코드로 다시 실행했다. warm-up은 현재 규칙인 max(120일, 전략 warm-up)이고, 공통 비용(`configs/costs.yaml`)과 공통 위험(`configs/risk.yaml`)을 쓴다. 기간은 BTCUSDT+ETHUSDT 동시, train 2021-10-09~2024-09-30, validation 2024-10-01~2025-09-30이다. 등록 실행은 33회다(후보 5개 × {train, val, val 스트레스 3종} = 25회, A2 인접 표면 8회).
- **스트레스(validation)**: `fee=2`(테이커·메이커 수수료 2배), `spread=3,impact=3,latency=1000`(이하 exec3), 둘을 합친 `fee=2,spread=3,impact=3,latency=1000`(이하 all).
- **기준 전략**: `evaluation/baselines.py`로 1m 데이터에서 해석적으로 계산했다(엔진 위험 크기 규칙으로는 1x 보유를 표현할 수 없음).
  - 현금: 0%, MDD 0.
  - buy&hold 1x 롱(명목가 = 초기 자본, 자본 전체를 담보로 써 청산 없음):
    `P_in = open₀·(1+slip)`, `qty = E0/P_in`, `fee_in = taker·qty·P_in`, `funding_k = −qty·mark(정산 직전 1분 종가)·rate_k`(엔진과 같은 부호),
    `E_t = E0 − fee_in + qty·(close_t − P_in) + Σ funding`, 마지막 1분 종가에서 `P_out = close·(1−slip)`로 청산하고 `fee_out` 차감.
    slip는 엔진 시장가와 같은 `CostModel.taker_slip_bps`(half spread + √impact + 1σ 지연)다. MDD는 엔진과 같이 시간별 자본 기준이다.
  - "+10% halt" 변형: 공통 10% 낙폭 중단 규칙을 그대로 적용(1분 종가 자본이 고점 대비 10% 하락하면 다음 1분 시가에 청산하고 이후 현금). 일일 손실 2% 규칙은 신규 진입만 막으므로 단일 진입 B&H에는 영향이 없다. 거래당 0.25% 위험 규칙은 손절이 없는 B&H에 적용할 수 없다. 이것이 후보와의 차이다.
  - 단순 추세 기준(4h 30일 수익률 부호)은 따로 만들지 않았다. **A2가 바로 그 단순 추세 기준**이다(sign(close/close₋₁₈₀)−1, 4h).
- **순위 규칙**(`configs/experiment.yaml`, 결과 확인 전 동결): 위험 위반·회계 오류·누수를 제외하고, 거래 ≥ 30건인 후보를 validation 비용 차감 net_return / max_dd 순으로 정렬한다.
- 지표 산식은 `engine/metrics.py`를 따른다. Sharpe = 일간(UTC) 수익률 평균/표준편차 × √365, rf = 0. MDD는 시간별 자본 기준. PF = 이익 거래 합 / |손실 거래 합|.

## 3. 감사 결과

### 3.1 (a) 인과성 — 누수 없음

- `engine.strategy.check_causality`(target, stop)에 tp·size_mult 비교를 더한 확장 검사(`evaluation/audits.py: causality_ext`)를 썼다. 실제 BTC·ETH 데이터(2021-10-09~2025-09-30, test 미사용)에서 후보·심볼마다 절단 10개 → **5개 후보 × 2심볼 모두 불일치 0**.
- 펀딩 입력은 절단 시점(t + TF)까지 정산된 행만 넘겼다. B2·C2의 펀딩 필터는 searchsorted로 봉 종료 시각 이하만 쓴다. 엔진 실행기에는 split 끝까지의 펀딩이 넘어가지만 전략 코드가 인과적으로 잘라 쓴다는 점을 확인했다.

### 3.2 (b) 시작점 절단 / 실시간 동등성 — 불일치 0

- 실시간 모의거래(`engine/live.py` `decide()`)는 약 150일 1m 창(`bootstrap_days: 150`, 152일에서 잘라냄)으로 전체를 다시 계산한다. A2·B2·C1·C2는 모두 내부에 포지션 상태기계(그림자 포지션)가 있어 시작점에 의존할 수 있다.

### 3.4 회계 대사

`evaluation/reconcile.py`로 후보 × {train, val} 10개 실행을 register=False로 다시 실행해 대사했다. 결과는 모두 오차 0(<1e-9 USDT)이다.
(1) 초기자본 + Σ원장 = 현금 잔고, (2) Σ체결 수수료 = −Σ원장 수수료, Σ실현손익 일치, (3) 체결로 재구성한 미청산 포지션 시가평가 + 잔고 = 최종 자본, (4) 닫힌 거래 순손익 + 열린 거래 + 미실현 = 최종 자본 − 초기자본.
첫 시도에서 A2-m3 val에 54.96 USDT 차이가 났다. 원인은 기간 말 미청산 포지션의 미실현 손익으로, 엔진 오류가 아니라 평가 스크립트 쪽 문제였다(수정 완료).

  **검증 한계**: SPEC.md가 git에 처음 들어간 것은 결과와 같은 커밋(b3fc1b8, 18:10:57)이다. "테스트 전 기재"는 registry 타임스탬프 순서와 문서 서술로만 뒷받침되고 git으로는 독립 확인이 안 된다. 또 A2 자체는 A1 실패를 본 뒤 꺼낸 대안이다(train에서의 선택이라 규정 위반은 아니다).
- **Deflated Sharpe**(Bailey & López de Prado 2014). A2-m3 val 일간 SR 0.0695(연 1.33), T = 365일:
  - SR > 0의 확률(PSR) = 0.92 → 다중검정 보정 전에도 95% 유의 수준에 미달한다.
  - DSR(시행 4 = A2 val 슬롯, 귀무 분산 1/T) = 0.62. 팀 A val Sharpe의 실측 분산을 쓰면 0.77. 프로젝트 전체 train 설정 34개를 시행으로 보면 **0.20**.
  - A2-m2도 0.61 / 0.77 / 0.18로 같은 결론이다. **validation 1년만으로는 A2의 우위가 통계적으로 입증되지 않는다.**
  - train(약 3년, 연 SR 1.37)을 합치면 근거가 강해진다(t ≈ 2.4). 다만 train은 A1 → A2 전환 판단에 쓰였다.
- 인접 표면 평균으로 본 감액은 4절 참조.

## 6. 발견된 엔진·프로세스 이슈 (수정하지 않음, 총괄에 보고)

1. **손절 체결 낙관**(3.3 #1): 1m 트리거 시 트리거 가격으로 체결한다. 권고: 보고용 스트레스 옵션 추가(예: 트리거와 해당 1m 종가 중 불리한 값, 또는 +k·σ bp). 기본 비용은 바꾸지 않는다.
2. **지연은 비용으로만 반영**(3.3 #2): 실제 체결 시점을 늦추지 않는다. 영향은 작다.
3. **낙폭 판정이 종가 기준**이고 MDD가 시간별 스냅샷이다(3.3 #5). 시간 내 낙폭을 보고할 필요가 있다.
4. `engine.strategy.check_causality`는 target·stop만 비교하고 **tp·size_mult는 검사하지 않는다**. 평가팀 확장 검사로 보완했다(`evaluation/audits.py`).
5. `run()`이 result id를 반환하지 않아 note로 역조회해야 한다(사용성). id 고유성은 초 단위 + pid에 의존한다(현재 충돌 없음, 100행 모두 고유).
6. 기간 말 미청산 포지션을 청산 비용 없이 평가한다(영향 무시 가능).
7. C1은 실시간 `bootstrap_days`가 약 95일 미만이면 백테스트와 어긋난다(3.2). 현재 150일은 안전하다. 설정 변경 시 주의.
8. A2 "사전 선언" 시각을 git으로 확인할 수 없다(3.5). 앞으로는 선언을 결과 전에 별도 커밋하는 것을 권고한다.

## 7. 동결(10/11 18:00 KST) 전까지 해도 되는 일 — test 오염 없이

1. **test 구간·`--final` 사용 금지 유지.** A2 파라미터를 바꾸지 않는다(4.4의 m2·L240 우위는 validation을 본 뒤의 관찰이다). B/C 팀이 validation을 보고 새 변형을 만드는 것도 금지한다(시행 수만 늘고 선택 편향이 커진다).
2. **최종 test 계획을 지금 문서로 동결**: 대상(A2-m3, A2-m2 두 개; 동결 순위 규칙상 m2가 1위이고 둘은 사실상 동률임을 명시), 성공 기준(비용 차감 순수익 > 0, PF > 1, 거래 ≥ 30, 10% 중단 없음), 비교 기준(현금, B&H BTC 1x 및 +halt 변형), 같은 스트레스 3종을 함께 보고. 폐기 후보(B2, C1, C2)는 실패 기록으로 test에서 1회 함께 보고해도 되지만 선택에는 쓰지 않는다.
3. **엔진 보강은 보고용 스트레스로만**(손절 슬리피지 스트레스, 시간 내 MDD 보고). 기본 비용·체결 규칙을 validation 결과를 보고 바꾸지 않는다. 바꾼다면 동결 전에 모든 후보에 똑같이 적용하고 재실행 기록을 남긴다.
4. **실시간 모의거래 대조**: 모의거래 기간의 1m 데이터를 같은 엔진으로 재생해 실시간 결정(진입·손절 이동)과 백테스트 결정이 일치하는지 대조한다. 이것은 수익성이 아니라 구현 동등성 검증이다.
5. 최종 보고서에 위 약점(2025Q3·ETH·롱 집중, BTC 무우위, B&H BTC 미달, DSR 비유의)을 그대로 싣는다.
